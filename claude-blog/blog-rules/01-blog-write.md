# /blog write — 新文章生成

从话题、简报或大纲写出完整博客文章。每篇文章遵循 6 大支柱双优化（Google 排名 + AI 引用）。

---

## 7阶段工作流

### Phase 1：话题理解

询问用户：
- 目标受众（写给谁？）
- 主关键词 / 搜索意图
- 目标字数（默认 2000-2500 字）
- 平台/格式（MDX、Markdown、HTML — 有项目时自动检测）

如果已有简报，加载后跳至 Phase 1.5。

---

### Phase 1.5：模板选择（12 种）

根据话题和搜索意图自动匹配：

| 信号 | 模板 | 目标字数 |
|------|------|---------|
| "How to..."、流程、步骤 | `how-to-guide` | 2000-2500 字 |
| "Best X"、"Top N"、列表 | `listicle` | 1500-2000 字 |
| 客户案例、前后对比、指标 | `case-study` | 1500-2000 字 |
| "X vs Y"、比较、替代品 | `comparison` | 1500-2000 字 |
| 宽泛话题、权威综合指南 | `pillar-page` | 3000-4000 字 |
| "X 值得买吗"、产品评测 | `product-review` | 1500-2000 字 |
| 观点、预测、行业解读 | `thought-leadership` | 1500-2500 字 |
| 专家引用、多来源汇总 | `roundup` | 1500-2000 字 |
| 代码演示、工具操作、技术 | `tutorial` | 2000-3000 字 |
| 突发新闻、算法更新、事件 | `news-analysis` | 800-1200 字 |
| 调查结果、实验、原始数据 | `data-research` | 2000-3000 字 |
| 问答、知识库、"What is X" | `faq-knowledge` | 1500-2000 字 |

---

### Phase 2：研究

启动 `blog-researcher` Agent 或内联 WebSearch：

1. **找 8-12 条最新统计数据**（优先 2025-2026）
   - 搜索：`[topic] study 2025 2026 data statistics`
   - 仅使用 Tier 1-3 来源
   - 记录：数据、来源名、URL、日期、方法

2. **找封面图**（宽幅、高质量、1200×630）
   - 优先：`site:pixabay.com [topic] wide banner`
   - 备选：`site:unsplash.com [topic] wide`
   - 兜底：`site:pexels.com [topic] wide banner`
   - 或通过 `blog-chart` 生成文字+渐变 SVG 封面
   - 或通过 `blog-image` 生成 AI 图片（需 nanobanana-mcp）

3. **找 3-5 张内文图**（Pixabay 优先，验证 URL 返回 HTTP 200）

4. **规划 2-4 个数据可视化**（选择不同图表类型）

5. **AI 图片生成**（可选）：库存照片不足时补充，不替代

6. **NotebookLM 研究**（可选）：用户有相关 Notebook 时调用，视为 Tier 1 来源

7. **找 2-3 个相关 YouTube 视频**（质量评分 ≥ 50/100）

---

### Phase 3：大纲生成（需用户确认后才写）

```
# [标题 — 问题格式，含主关键词]

## 引言（100-150 字）
- 以惊人统计数据开头
- 问题/机会陈述
- 读者将学到什么

> **Key Takeaways**
> - [含统计的核心发现]
> - [第二条关键洞察]
> - [第三条可行动要点]

## H2：[问题格式]（300-400 字）
- 答案优先段落（40-60 字，含统计+来源）
- 支持性证据
- [图片占位]
- [CITATION CAPSULE 占位]
- [INTERNAL-LINK: 锚文本 → 目标描述]

## H2：[问题格式]（300-400 字）
- 答案优先段落
- [图表：类型 + 数据描述]
- [CITATION CAPSULE 占位]

## FAQ（3-5 个问题，每个回答 40-60 字）

## 结尾（100-150 字）
- 关键要点
- CTA
- [INTERNAL-LINK]
```

**视觉节奏：** 每 300-500 字插入 `[IMAGE]` / `[CHART]` / `[VIDEO]` / `[CALLOUT]`，类型交替出现。

---

### Phase 4：图表生成

当研究发现图表价值数据时：
1. 使用多样性规则选择图表类型（一篇文章不重复类型）
2. 调用 `blog-chart` 子技能
3. 在 `<figure>` 标签内嵌入 SVG
4. 每 2000 字目标 2-4 个图表，均匀分布

---

### Phase 5：内容写作规则

#### 5a. 前置元数据（Frontmatter）

```yaml
---
title: "[问题格式标题，含主关键词]"
description: "[含1个统计，150-160字符]"
coverImage: "[URL]"
coverImageAlt: "[封面图描述]"
ogImage: "[同 coverImage 或自定义]"
date: "YYYY-MM-DD"
lastUpdated: "YYYY-MM-DD"
author: "[作者姓名]"
tags: ["keyword1", "keyword2", "keyword3"]
---
```

#### 5b. Key Takeaways 摘要框

放在引言之后、第一个 H2 之前：

```markdown
> **Key Takeaways**
> - [含统计的核心发现]（来源，年份）
> - [第二条关键洞察]
> - [第三条可行动要点]
```

要求：
- 3-5 条要点，合计 40-60 字
- 独立可读（不读文章也能理解）
- 至少含 1 条统计数据 + 来源
- 默认标签："Key Takeaways"（人格激活时用人格设定的标签）

#### 5c. 答案优先格式（关键）

每个 H2 部分的第一段必须包含：
- 至少 1 条带来源归因的具体统计数据
- 对标题隐含问题的直接回答

```markdown
## X 如何影响 Y？

[来源统计]（[来源名](url)，年份）。[直接回答问题，
1-2句解释含义和对读者的影响。]
```

#### 5d. 信息增益标记（至少 2-3 个）

| 标记 | 适用内容 |
|------|---------|
| `[ORIGINAL DATA]` | 专有调查、实验、A/B测试、第一手案例数据 |
| `[PERSONAL EXPERIENCE]` | 亲身观察、直接参与的经验 |
| `[UNIQUE INSIGHT]` | 他人未做过的分析、有数据支撑的反常识观点 |

格式：
```markdown
<!-- [ORIGINAL DATA] -->
```
或可见标注：
```markdown
> **Our finding:** [有具体数据支撑的原始观察]
```

#### 5e. 引用胶囊（每个 H2 一个）

每个主要 H2 部分内，生成一段 40-60 字的独立可引用文字：

要求：
- 40-60 字，独立自洽（脱离上下文也能理解）
- 包含：一个具体声明 + 一个数据点 + 来源归因
- 声明式、可被 AI 系统直接引用的风格

示例：
```markdown
根据 2026 年 Gartner 研究，58% 的企业买家在联系供应商前
会先咨询 AI 助手（[Gartner](https://www.gartner.com)，2026年）。
这意味着 B2B 内容必须足够简洁，让 AI 系统能提取并在回应中引用。
```

#### 5f. 内链占位符

格式：`[INTERNAL-LINK: 锚文本 → 目标描述]`

布置位置：
- 引言（链接到相关支柱内容）
- 每个 H2 部分（链接到支持文章）
- FAQ 部分（链接到深度内容）
- 结尾（链接到读者下一步应读的内容）

每 2000 字目标 5-10 个内链区域，使用描述性锚文本（绝不用"点击此处"）。

#### 5g. 段落规则

- 每段：40-80 字（绝不超过 150 字）
- 每句：最长 15-20 字
- 每段首句放最重要的信息
- 目标 Flesch 可读性：60-70

#### 5h. 标题规则

- 仅一个 H1（标题）
- H2 为主要部分（60-70% 为问题格式）
- H3 仅用于子部分（绝不跳级）
- 主关键词自然出现在 2-3 个标题中

#### 5i. 图片嵌入

标准 Markdown：
```markdown
![描述性 alt 文本 — 自然包含话题关键词](https://cdn.pixabay.com/photo/...)
```

- 图片放在 H2 标题后、正文前
- 均匀分布，不集中
- Alt 文本是完整描述句

#### 5j. 图表嵌入

```html
<figure>
  <svg viewBox="0 0 560 380" ...>...</svg>
  <figcaption>Source: [来源名]，[年份]</figcaption>
</figure>
```

#### 5k. 视频嵌入

使用 `references/video-embeds.md` 中的 srcdoc 懒加载模式，含 aria-label 和 noscript 降级。

#### 5l. 引用格式

```markdown
有机 CTR 随 AI Overviews 下降 61%（[Seer Interactive](url)，2025）。
```

#### 5m. FAQ 部分

3-5 个问题，每个回答 40-60 字，含统计数据。

#### 5n. 内链

- 每 2000 字 5-10 个内链
- 自然链接到相关已有内容
- 描述性锚文本

---

### Phase 6：质量检查（19 条）

**结构与内容：**
1. 每个 H2 以统计 + 来源开头
2. 无段落超过 150 字
3. 所有统计有 Tier 1-3 命名来源
4. 2-4 个图表，类型多样
5. 3-5 张内文图，有描述性 alt 文本
6. frontmatter 有封面图（coverImage + ogImage）
7. FAQ 部分有 3-5 个问题
8. 标题层级干净（H1 → H2 → H3）
9. Meta 描述 150-160 字符，含统计

**新元素：**
10. Key Takeaways 摘要框（引言后，40-60 字，含统计）
11. 至少 2-3 个信息增益标记
12. 引用胶囊（每个主要 H2，40-60 字，独立自洽）
13. 内链区域（引言/H2/FAQ/结尾都有标注）
14. 无禁用 AI 词汇

**自然度：**
15. 句子长度有变化（混合短句 8 字和长句 25 字）
16. 已扫描并清除禁词列表中的词
17. 自然使用缩略词（it's、we've、don't、isn't）
18. 每 200-300 字至少 1 个反问句
19. 2-3 个 YouTube 嵌入（懒加载、aria-label、noscript）

---

### Phase 7：交付摘要格式

```
## 博客文章完成：[标题]

### 使用模板
- [模板名称]

### 统计数据
- [N] 条来自 Tier 1-3 的统计数据
- [N] 个独立来源

### 视觉元素
- 封面图：[来源]
- [N] 张内文图
- [N] 个 SVG 图表（类型：...）
- [N] 个 YouTube 视频嵌入

### 双优化元素
- Key Takeaways 摘要框：存在（N 字）
- 信息增益标记：[N] 个（类型：...）
- 引用胶囊：[N] 个
- 内链区域：[N] 个标注

### 结构
- [N] 个 H2 部分（答案优先格式）
- [N] 个 FAQ 问题（含 Schema）
- 字数：约 [N] 字
- 预计阅读时间：[N] 分钟

### 自然度
- 句子长度方差：[通过/未通过]
- AI 词汇扫描：[通过/未通过]
- 使用缩略词：[是/否]
- 反问句：[N] 个

### 后续步骤
- 审阅并根据品牌声音定制
- 将 [INTERNAL-LINK] 占位符替换为实际 URL
- 运行 `/blog analyze <file>` 验证质量分数
- 运行 `/blog schema <file>` 生成结构化数据
- 运行 `/blog audio generate <file>` 生成音频（可选）
```
