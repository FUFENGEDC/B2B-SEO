# /blog audit — 全站博客健康评估

对项目中所有博客文章进行全面健康评估。扫描质量分、孤儿页、话题蚕食、陈旧内容和 AI 引用就绪度。使用并行子 Agent 进行高效分析，生成优先行动队列。

---

## 7步审计流程

### Step 1：发现博客文件

扫描项目中所有博客内容文件：
- Glob 查找 `*.md`, `*.mdx`, `*.html`
- 常见路径检查：
  - `content/`、`posts/`、`blog/`、`src/content/`
  - `_posts/`、`pages/blog/`、`articles/`、`src/pages/blog/`
- 过滤非博客文件：README, CHANGELOG, LICENSE, config files, SKILL.md, package.json, node_modules
- 报告："在 [目录] 中找到 N 个博客文件"

如果标准位置未找到博客文件，搜索整个项目根目录查找含博客式前置元数据（title, date, description）的 Markdown 文件。

---

### Step 2：并行分析（6个子 Agent）

通过 Task 工具并行启动子 Agent：

#### 内容质量 Agent
- 按 30 分内容质量量表评分
- 检查段落长度（目标 40-80 字，硬限制 150 字）
- 检查句子长度（目标 15-20 字）
- 评估标题结构和问题格式标题
- 评估可读性（Flesch 阅读简便性目标 60-70）

#### SEO 优化 Agent
- 检查每篇文章的站内 SEO 元素：
  - 标题标签长度（50-60 字符）
  - Meta 描述（150-160 字符，含统计）
  - H1 存在且唯一
  - 图片 alt 文本覆盖
  - 内链和外链数量
  - URL slug 质量

#### Schema 验证 Agent
- 检测所有文章中的结构化数据
- 验证 BlogPosting Schema 完整性
- 检查 FAQ Schema 存在和格式
- 验证 dateModified 与 lastUpdated 前置元数据匹配
- 标记缺失或格式错误的 Schema

#### 链接健康 Agent
- 映射所有文章的内链
- 构建有向链接图
- 检测孤儿页（零个入站内链）
- 检测死胡同页（零个出站内链）
- 检查断裂的内链目标
- 推荐双向链接机会

#### 新鲜度检查 Agent
- 从每篇文章前置元数据读取 `lastUpdated` 或 `dateModified`
- 计算每篇文章距上次更新的天数
- 标记 90+ 天未更新的文章
- 按刷新优先级分类

#### AI 就绪度 Agent
- 评分每篇文章的 AI 引用就绪度
- 检查段落级可引用性（120-180 字的部分）
- 评估问答格式和实体清晰度
- 检查 TL;DR 框和引用胶囊
- 评估 AI 爬虫可访问性

---

### Step 3：话题蚕食检测

跨所有文章分析关键词竞争：

1. 从每篇文章提取主关键词/话题：
   - 标题文字
   - H1 标题
   - Meta 描述
   - 第一段
2. 规范化关键词（小写，去除停用词）
3. 检测多篇文章针对同一主关键词的情况
4. 为每个竞争文章提供以下建议之一：
   - **合并（Merge）**：将两篇薄文章合并为一篇强文章
   - **重定向（Redirect）**：301 重定向较弱的 URL 到较强的
   - **差异化（Differentiate）**：调整文章重点使其针对不同意图

---

### Step 4：孤儿页检测

构建并分析内链图：

1. 为每篇博客文章提取所有内链（相对和绝对）
2. 构建邻接图：`{ 页面 -> [它链接到的页面] }`
3. 构建反向图：`{ 页面 -> [链接到它的页面] }`
4. 识别孤儿页：零个入站内链的文章
5. 识别死胡同页：零个出站内链的文章
6. 为每个孤儿页推荐 2-3 个应该链接到它的现有文章（基于话题相关性）

---

### Step 5：陈旧内容检测

审计所有文章的内容新鲜度：

1. 读取前置元数据字段：`lastUpdated`, `dateModified`, `date`, `updated`
2. 计算每篇文章距上次更新的天数
3. 按刷新优先级分类：
   - **高**（>180天）：可能已过时，统计数据可能陈旧
   - **中**（90-180天）：审查准确性，更新统计
   - **低**（<90天）：最近已更新，无需立即行动
4. 估算每篇文章的刷新工作量：
   - 轻度刷新：更新统计，检查链接（1-2小时）
   - 中度刷新：重写部分，添加新数据（3-4小时）
   - 重度刷新：建议全面重写（5小时以上）

---

---

### Step 7：保存报告

将完整报告保存至项目根目录的 `blog-audit-report.md`。

保存后通知用户：
- 报告位置：`[项目根目录]/blog-audit-report.md`
- 发现摘要（文章总数、平均分、关键问题数量）
- 建议先对最低分文章运行 `/blog analyze <file>`
- 建议对关键文章运行 `/blog geo <file>` 进行 AI 引用优化
