# /blog factcheck — 数据核实

通过获取引用来源 URL 并检查声明数据是否实际出现在页面上，来验证博客文章中的统计数据和声明。

---

## 4步工作流

### Step 1：读取博客文章

读取目标文件，识别所有包含数据声明的部分。

### Step 2：提取统计声明

扫描全文，找出每个包含数字、百分比、美元金额或命名来源的声明。建立声明列表，字段如下：

| 字段 | 描述 |
|------|------|
| claim_text | 包含统计的确切句子或短语 |
| value | 数值（如 "42%", "$1.2M", "3x"） |
| attribution | 命名来源（如 "HubSpot", "Gartner 2025"） |
| url | 引用的 URL（来自 Markdown 链接或括号引注） |
| location | 声明所在的标题或行号 |

### Step 3：核实已引用声明

对每个包含 URL 的声明：

1. 通过 WebFetch 获取来源页面
2. 在返回内容中搜索具体数值
3. 找到精确值后，检查周围上下文是否与声明话题匹配
4. 分配置信度分数（见下方评分标准）

**顺序处理声明，避免对来源站点限速。**

### Step 4：标记未引用声明

对没有 URL 的声明：
- 标记状态为 UNVERIFIED
- 建议用户可以运行的搜索查询来找来源
- 如归因命名了特定组织，建议其官网域名

---

## 声明提取模式

**完全引用**（最高优先级）：
- `[数字]% [声明] ([来源], [年份])` — 括号引注
- `[声明] [数字]% ... [Markdown 链接到来源]` — 行内链接
- `According to [来源], [数字]...` — 归因前置

**未引用统计**（标记需要来源）：
- `[数字]% of [名词短语]` — 独立百分比
- `[数字]x more/less/higher/lower` — 倍数声明
- `$[数字] [声明]` — 无归因的美元数字

**弱信号**（提取前检查上下文）：
- `studies show`, `research indicates`, `data suggests` + 附近数字
- `survey found`, `report reveals`, `analysis shows` + 附近数字
- 孤立的整数（如 "millions of users"）— 跳过，除非具体

---

## 核实评分

| 分数 | 状态 | 标准 |
|------|------|------|
| 1.0 | VERIFIED（已核实） | 引用页面在匹配上下文中找到精确数字 |
| 0.7-0.9 | PARAPHRASE（换言） | 找到类似数据，但措辞、四舍五入或时间框架不同 |
| 0.3-0.6 | WEAK（弱） | 来源页面存在且涵盖话题，但具体统计不可见 |
| 0.0 | NOT FOUND（未找到） | 引用页面完全不含所声明的数据 |
| N/A | UNVERIFIED（未核实） | 声明没有提供来源 URL |

**评分指南：**
- 声明 "43%"，来源说 "近一半" → 0.8
- 声明 "2024年" 数据，来源只有 "2023年" → 0.7
- 声明引用主页，统计在子页面 → 0.3
- 404 或无法访问的 URL → 0.0

## 输出格式

```
### 核实报告：[文章标题]

**文件**：[路径]
**找到的声明**：[总数]
**已核实**：[数量] | **换言**：[数量] | **弱**：[数量] | **未找到**：[数量] | **未核实**：[数量]

| # | 声明 | 来源 URL | 分数 | 状态 | 备注 |
|---|------|---------|------|------|------|
| 1 | "73% of marketers..." | https://example.com/report | 1.0 | VERIFIED | 在第3节找到精确匹配 |
| 2 | "5x ROI improvement" | https://example.com/study | 0.8 | PARAPHRASE | 来源说"近5x" |
| 3 | "60% prefer video" | (无) | N/A | UNVERIFIED | 尝试搜索："video preference statistics 2025" |

### 推荐行动
- [需要来源 URL 的声明列表]
- [分数弱或未找到、需要替换来源的声明列表]
- [来源数据可能已过时的声明列表]
```

---

## 与 blog-analyze 集成

本技能可作为 `blog-analyze` 的可选深度核实步骤调用。从分析器调用时，只在分析报告中标记分数低于 0.7 的声明。

独立使用：`/blog factcheck path/to/post.md`

---

## 限制

| 限制 | 处理方式 |
|------|---------|
| 付费内容 | WebFetch 无法访问登录墙后的内容。评为 WEAK(0.5)，备注检测到付费墙。 |
| 动态页面 | JavaScript 渲染的内容可能无法通过 WebFetch 获取。如页面返回极少内容，在状态中注明。 |
| PDF 来源 | WebFetch 可能无法可靠提取 PDF 文字。标记 PDF URL 供人工核实。 |
| 归档页面 | URL 返回 404 时，建议检查 web.archive.org |
| 限速 | 每次运行最多处理 10 个 URL，避免对来源服务器过载。超过 10 个引用 URL 时，核实前 10 个，其余标记为 SKIPPED。 |
