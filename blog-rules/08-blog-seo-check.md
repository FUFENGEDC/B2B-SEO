# /blog seo-check — 写后 SEO 验证

对已完成博客文章进行全面的站内 SEO 验证，生成通过/失败清单及每条失败的具体修复建议。设计用于写完后、发布前运行。

---

## 工作流

### Step 1：读取内容

读取目标文件并提取：
- **前置元数据**：title, description, date, lastUpdated, author, tags, canonical, og:image, slug/URL
- **标题结构**：H1, H2, H3 层级（含完整文字）
- **链接**：所有内链和外链及其锚文本
- **Meta 标签**：OG 标签、Twitter Card 标签、Canonical URL
- **正文内容**：关键词和结构分析的全文

如果用户提供 URL 而非文件路径，使用 WebFetch 获取页面并提取相关元素。

---

### Step 2：标题标签验证

| 检查项 | 通过标准 |
|--------|---------|
| 字符数 | 40-60 字符（不在 SERP 中截断） |
| 关键词位置 | 主关键词在标题前半段 |
| 力量词 | 至少含一个力量词（Guide, Best, How, Why, Essential, Proven, Complete 等） |
| 截断风险 | 60 字符处截断不丢失关键含义 |
| 唯一性 | 非通用，具体反映内容 |

---

### Step 3：Meta 描述

| 检查项 | 通过标准 |
|--------|---------|
| 字符数 | 150-160 字符 |
| 含统计 | 至少含 1 个具体数字或数据点 |
| 价值主张 | 结尾有清晰的读者收益或价值主张 |
| 关键词 | 主关键词自然出现（不堆砌） |
| 不重复 | 关键词最多出现 1 次 |
| 行动暗示 | 暗示行动（learn, discover, find out, see） |

---

### Step 4：标题层级

| 检查项 | 通过标准 |
|--------|---------|
| 唯一 H1 | 恰好 1 个 H1 标签（标题） |
| 无跳级 | H1→H2→H3，绝不 H1→H3 或 H2→H4 |
| 关键词在标题中 | 主关键词在 2-3 个标题中自然出现 |
| 问题格式 | 60-70% 的 H2 为问题格式 |
| H2 数量 | 标准博客文章 6-8 个 H2 部分 |
| 标题长度 | 每个标题 70 字符以内 |

---

### Step 5：内链

| 检查项 | 通过标准 |
|--------|---------|
| 链接数量 | 每篇文章 3-10 个内链 |
| 锚文本 | 描述性（不用"点击此处"或"阅读更多"） |
| 双向链接 | 检查被链接页面是否也有回链（标记如果没有） |
| 无孤立状态 | 文章链接到站内至少 3 个其他页面 |
| 链接分布 | 链接分散在文章各处，不集中堆放 |
| 无自链 | 文章不链接到自身 |

---

### Step 5.5：链接去重

| 检查项 | 通过标准 |
|--------|---------|
| 无重复 URL | 正文中每个 URL 最多出现 1 次 |
| 保留最佳实例 | 有重复时，保留锚文本最具描述性的那个 |
| 导航链接豁免 | 页头/页脚导航链接不计入正文去重 |
| Fragment 规范化 | 不同 #fragment 的 URL 视为同一 URL |

对每个重复链接：
1. 规范化 URL（去掉尾部斜线、查询参数、fragment）
2. 按锚文本描述性评分（含关键词 > 通用词）
3. 建议保留评分最高的，删除其他
4. 每个重复从 SEO 优化分中扣 1 分

> **参考数据**：Google 每页每 URL 记录 1-2 个锚文本（Zyppy 2023）。最优：正文每个 URL 只链接 1 次；每 2000 字 5-10 个内链；每页最多约 50 个链接。

---

### Step 6：外链

| 检查项 | 通过标准 |
|--------|---------|
| 来源层级 | 仅链接 Tier 1-3 来源（权威，不是 SEO 博客） |
| 断链检查 | 用 WebFetch 验证主要外链可访问 |
| Rel 属性 | 外链有适当 rel 属性（赞助/UGC 链接用 nofollow） |
| 链接数量 | 至少 3 个指向权威来源的外链 |
| 无竞争对手链接 | 不必要地链接到直接竞争对手 |

---

### Step 7：Canonical URL

| 检查项 | 通过标准 |
|--------|---------|
| 存在 | Canonical URL 在前置元数据或 meta 标签中定义 |
| 格式正确 | 完整绝对 URL（https://domain.com/path） |
| 尾斜线一致 | 与站点惯例一致（不混用） |
| 自引用 | Canonical 指向页面自身（除非有意跨域） |

---

### Step 8：OG Meta 标签

| 检查项 | 通过标准 |
|--------|---------|
| og:title | 存在，与标题标签匹配或互补 |
| og:description | 存在，150-160 字符，有社交分享吸引力 |
| og:image | 存在，最小 1200×630，绝对 URL |
| og:type | 博客文章设为 "article" |
| og:url | 存在，与 Canonical URL 匹配 |
| og:site_name | 存在，与站点/品牌名匹配 |

---

### Step 9：Twitter Card

| 检查项 | 通过标准 |
|--------|---------|
| twitter:card | 博客文章设为 "summary_large_image" |
| twitter:title | 存在，70 字符以内 |
| twitter:description | 存在，200 字符以内 |
| twitter:image | 存在，与 og:image 相同或相似 |
| twitter:site | 如果站点有 Twitter/X 账号则存在 |

---

### Step 10：URL 结构

| 检查项 | 通过标准 |
|--------|---------|
| 长度 | 短 — 路径部分 75 字符以内 |
| 含关键词 | URL slug 中有主关键词或近似变体 |
| 无日期 | URL 不含 /2025/ 或 /2026/ 日期段 |
| 无特殊字符 | 仅小写字母、数字和连字符 |
| 小写 | 整个 URL 路径小写 |
| 少停用词 | slug 中少用 "the", "a", "and", "of" |
| 无扩展名 | URL 中无 .html 或 .php |

---

### Step 11：生成报告

```
## SEO 验证报告：[标题]

**文件**：[路径或 URL]
**日期**：[检查日期]
**总体**：[X/Y 项通过] — [通过/需改进/失败]

### 结果

| # | 检查项 | 状态 | 详情 | 修复方式 |
|---|--------|------|------|---------|
| 1 | 标题长度 | PASS | 52字符 | — |
| 2 | 标题关键词 | PASS | "关键词"在前半段 | — |
| 3 | 标题力量词 | FAIL | 未找到力量词 | 添加 "Guide"、"Essential" 或 "Complete" |
| 4 | Meta 描述长度 | PASS | 155字符 | — |
| 5 | Meta 描述含统计 | FAIL | 无数字 | 添加文章中的一条关键统计 |

### 摘要

**通过**：[N] 项
**失败**：[N] 项

### 优先修复
1. [最高影响的修复 — 改什么、在哪里]
2. [第二影响]
3. [第三影响]

### 备注
- [SEO 整体健康的观察]
- [清单以外的改进建议]
```

**状态值：**
- **PASS**：满足标准
- **FAIL**：不满足标准，提供修复建议
- **WARN**：部分满足或边缘情况，提供推荐
- **N/A**：不适用（如站点无 Twitter/X 账号则 Twitter Card 标签不适用）

---

### 可选：实时性能检查（blog-google）

如果文章已发布且 blog-google 凭证可用：

1. 检查凭证：`python3 skills/blog-google/scripts/run.py google_auth --check --json`
2. 如果 Tier 0+，运行 PageSpeed：`python3 skills/blog-google/scripts/run.py pagespeed_check <url> --json`
3. 在报告中附加：
   - Lighthouse 性能、可访问性、最佳实践、SEO 分数
   - CWV 实地数据（LCP、INP、CLS）及红绿灯评级
   - 前3个优化机会及预计节省
4. 凭证不可用或 URL 未发布时静默降级。
